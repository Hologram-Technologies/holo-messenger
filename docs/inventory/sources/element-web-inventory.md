# Element Web/Desktop inventory

Source: github.com/element-hq/element-web at commit 07fa1225 (2026-11-18), read from a shallow clone. Behaviour is described in our own words; no source, strings or assets are copied. Paths are relative to `apps/web/src/` unless they start with `apps/`, `packages/` or `docs/`.

## A. Architecture

**Layers.**

1. Engine SDK (`matrix-js-sdk`, with the Rust crypto engine compiled to WASM). Owns the network, sync, the room and event model, encryption, calls. The app holds exactly one client, reached through `MatrixClientPeg.ts` and React contexts (`contexts/MatrixClientContext`, `contexts/SDKContextClass.ts`).
2. Stores and client state (`stores/`, `settings/SettingsStore.ts`, `device-listener/`, `Notifier.ts`, `LegacyCallHandler.tsx`). Long-lived singletons that listen to engine events and to a global action bus (`dispatcher/`), derive app state (room list, spaces, unread levels, right panel, widgets, calls, toasts) and emit change events.
3. View models (`viewmodels/`, `components/viewmodels/`). One per view; subscribe to stores and engine objects, hold a snapshot, expose actions. Pattern in `docs/MVVM.md`. Migration is partial: much logic still sits in large React "structures".
4. Views (`components/structures`, `components/views`, and `packages/shared-components` for engine-free presentational views). Platform specifics sit behind `BasePlatform.ts` (`vector/platform/` for web, PWA, Electron; shell in `apps/desktop`).

**Sync to screen.** `Lifecycle.ts` restores credentials, creates the client, starts crypto, then sync (classic, or sliding via `SlidingSyncManager.ts`). The engine applies each sync response to its `Room` objects and emits typed events (timeline, state, receipt, account data, membership, crypto status). Stores recompute and emit; view models update snapshots; views re-render. `TimelinePanel` reads a `TimelineWindow` over the room's live timeline and paginates on scroll. User intent runs the other way: view, view model or dispatcher action, engine call, local echo shown at once, confirmed or failed when the server answers.

**Engine concepts the client depends on, and where.**

- Homeserver, discovery, versions, capabilities: `utils/AutoDiscoveryUtils.tsx`, `SdkConfig.ts`, devtools.
- Login, registration, interactive auth, SSO, OAuth, QR rendezvous, guests: `Login.ts`, `Lifecycle.ts`, `components/structures/auth`, `utils/oauth`.
- Sync, sliding sync, filters, lazy-loaded members, sync state: `MatrixClientPeg.ts`, `LoggedInView`, `RoomStatusBar`.
- Room, membership (join, invite, leave, ban, knock), aliases, room versions and upgrades, tombstones: `RoomViewStore`, `createRoom.ts`, `RoomPreviewBar`.
- State events (name, topic, avatar, join rules, history visibility, guest access, power levels, encryption, pinned events, canonical alias, server ACL, space child and parent, widgets, policy rules, RTC membership): `TextForEvent.tsx`, room settings tabs.
- Timeline events and message types (text, emote, notice, image, video, audio, file, location, sticker, polls, beacons, call signalling, verification): `events/EventTileFactory.tsx`.
- Relations (edit, reaction, reply, thread, reference): composer, reactions, `ThreadView`.
- Receipts (public, private, threaded), fully-read marker, typing, presence: `TimelinePanel`, `TypingStore`, `Presence.ts`.
- Account data and room account data (direct chats, tags, ignored users, push rules, settings, space order, secrets): `SettingsStore`, `DMRoomMap`, `SpaceStore`.
- Crypto API (cross-signing, secret storage, key backup, verification, device and user trust, key export, dehydration): `SecurityManager.ts`, `device-listener/`, encryption settings.
- Media repository (upload, authenticated download, thumbnails, encrypted files, URL previews): `ContentMessages.ts`, `customisations/Media.ts`.
- Push rules, pushers, notification timeline: `Notifier.ts`, `RoomNotifs.ts`, notification settings.
- Search endpoint; local index on desktop: `Searching.ts`, `indexing/`.
- Room directory, user directory, room hierarchy, room summary: spotlight, `SpaceHierarchy`.
- Identity server (email and phone lookup, binding, email invites, terms): `IdentityAuthClient.tsx`, `AddThreepid.ts`.
- Integration manager, widgets and widget API, OpenID tokens: `integrations/`, `stores/widgets/`.
- WebRTC calls, TURN, MatrixRTC and LiveKit: `LegacyCallHandler.tsx`, `models/Call.ts`.
- Extended profiles, reporting, admin endpoints: `UserInfo`, report dialogs.
